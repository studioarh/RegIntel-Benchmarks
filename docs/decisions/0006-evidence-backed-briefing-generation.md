# 0006. Evidence-Backed Briefing Generation

**Date:** 27 September 2026 
**Status:** Accepted  

## Context
In Issue 5, the LangGraph pipeline was assembled with briefing and review nodes stubbed. We now need a production-grade briefing generator that transforms retrieved source chunks and extracted facts into an auditable, structured briefing for UK consumer-lending compliance analysts. Every factual claim must be backed by real source excerpts, analyst inferences must be explicitly demarcated from source facts, and weak evidence or invalid citations must be flagged rather than silently repaired.

## Decisions

### 1. Separation of LLM Draft Schema and System Model
   - Introduced `BriefingDraftLLMOutput` exclusively for structured LLM generation, enforcing `min_length=1` on `what_changed` to ensure the model does not return an empty report when evidence is provided.
   - Retained `RegulatoryBriefing` as the system state and persistence model without `min_length=1`, allowing safe storage of edge cases such as `insufficient_evidence` runs.
   - Kept metadata resolution (title, source URL, publication date) deterministic in Python rather than delegating it to the LLM.

### 2. Categorized Schema for Auditability
   - Replaced untyped claim strings with distinct models: `FactItem` (source obligations), `InterpretationItem` (reasoned sector impact tied to an obligation), and `KeyDateItem` (effective dates with fallback to "No effective date identified").
   - Decoupled `claim_kind` classification from LLM discretion by enforcing structure via schema design.

### 3. Deterministic Markdown Rendering and Grounding
   - Excerpts are populated via a Python lookup against retrieved `chunk_map` entries rather than generated by the LLM, eliminating excerpt hallucinations.
   - Citations and excerpts are formatted consistently across "What changed", "Why it may matter", and "Key dates".
   - The decision footer is set to `Pending Quality Gate Verification` to preserve architectural separation between briefing generation and the downstream quality gate.

### 4. Explicit Uncertainty Taxonomy
   - Rather than dropping invalid citations silently, the renderer marks them visibly (`[UNVERIFIED]`) and appends structured flags to `uncertainty_flags`:
     - `insufficient_evidence`: Triggered when retrieved chunks or extracted facts are empty.
     - `partial_invalid_citations_item_{index}`: Triggered when an item cites a mix of valid and unretrieved chunk IDs.
     - `unsupported_claim_item_{index}`: Triggered when all cited chunk IDs for an obligation are unretrieved or phantom UUIDs.
     - `unsupported_interpretation_basis_{index}`: Triggered when an analyst inference links to missing chunk IDs.
     - `unsupported_date_{index}`: Triggered when a specific deadline lacks source grounding.

## Consequences
- The briefing generator produces verifiable, template-conforming Markdown backed by immutable database chunks.
- Invalid citations and phantom claims surface directly in the uncertainty audit trail for downstream routing.
- The pipeline cleanly separates factual extraction from qualitative reasoning, satisfying compliance review requirements.
